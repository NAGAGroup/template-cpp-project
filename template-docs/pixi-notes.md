# Pixi field notes

Distilled notes from a full read of the pixi documentation (2026-08,
pixi 0.76.1) plus empirical findings from building this template. Kept in
the repo because understanding pixi deeply IS this template's subject
matter. Some items describe preview behavior that will change.

- lock_file: --frozen (install from lock, ignore manifest sync) vs --locked (fail if out of sync); PIXI_FROZEN/PIXI_LOCKED env vars; DOCTRINE: these are niche developer-side guards — CI/consumers should use default resolution semantics (virtual packages differ across hosts); satisfiability = envs+channels+packages matchspec-match lock (even timestamp/subdir); library-vs-app lock committing considerations; pixi-diff tooling.
- backends: "equal footing" — if()/target/plain deps ALL only shape the build env resolve, never the recipe → variant expansion works in conditional+target tables. Generated recipe + variants.yaml debuggable at .pixi/build/work/<pkg>--<hash>/debug/ (rebuild with raw rattler-build). PIXI_BUILD_BACKEND_OVERRIDE(_ALL) for backend dev. pixi-build-cmake passes -GNinja explicitly on the cmake command line (env CMAKE_GENERATOR cannot collide); `compilers` accepts ARBITRARY conda-build stems (m2w64_cxx → ${{ compiler('m2w64_cxx') }}), resolvable iff the variant keys exist; backend stdlib injection only consults `c_stdlib` (m2w64 stdlib keys are backend-inert).
- manifest ref: TOML 1.1; requires-pixi (USE IT); exclude-newer (supply-chain); solve-strategy lowest/lowest-direct; [constraints]; channel-priority; rich platforms reference (friendly keys incl cuda={driver,arch}); [package] field inheritance {workspace=true}; [package.build] extras: flags/build-number/build-string-prefix/secrets; run-exports 5 buckets + publish semantics (self-export unversioned; path specs dropped in binaries; conditional if() subtables OK); extra-dependencies/extras; run-deps `when` field.
- **solve-strategy semantics (empirical, 0.76.1)**: feature-level solve-strategy governs its env regardless of list position, INCLUDING source-package envs (unconstrained-direct-dep discriminator: xz resolved lowest inside test-lowest's surface). CAUSAL CHAIN for the surprising part: a consumed source package's HOST deps are resolved in a NESTED solve that does not inherit the env's strategy (defaults to highest), and the run-exports of those host packages are baked into the source record as FLOORS; the env solve then honors lowest-direct faithfully against an already-floored candidate set. DIAGNOSTIC FINGERPRINT: a doubled spec on a source record in the lock (the raw spec plus a tighter pin) is a run-export floor. Scope, stated honestly: min-version testing genuinely lowers UNFLOORED direct deps and cannot lower floored ones — no knob threads a strategy into the nested solve (discussion/feature-request territory, not a defect; pixi#5559 architectural umbrella, #6587 run-export-chaining context). Related but DISTINCT: pixi#5386 is lowest-direct correctly ignoring a TRANSITIVE dep — it does not explain a floored DIRECT dep. Cautionary tale: an earlier session misread a degenerate observable (spdlog floored at 1.15.3 = also highest-in-range) as "strategy ignored in source envs" — a causal claim needs a discriminating test with an UNCONSTRAINED observable.
- **Source-record staleness TRAP (cost us a false law)**: pixi's source-package identifier hash EXCLUDES recipe content, so editing a `recipe.yaml` alone does NOT invalidate the record — `pixi lock` happily keeps serving the old metadata, and a recipe change appears to have "no effect". Force re-resolution with `pixi update <package>` (targeted; note it rejects the whole command if any named package is only transitive). We concluded "rattler-recipe run_exports don't surface through pixi's source bridge" from exactly this artifact; a clean-rig test stamped them immediately, and after `pixi update` the real tree stamped them too.
- **feature composition (empirical, 0.76.1)**: dependency specs across composed features INTERSECT — disjoint specs on one package are unsolvable, order-irrelevant. Selectors compose only when they pin packages the base flavor does not declare.
- specs: MatchSpec build/build-number/channel/sha256/license/file-name; repodata v3 extras+flags on deps (CEP42/44, flags match [package.build].flags — FUTURE variant selector); `when` conditional deps (matchspec incl __virtuals, all/any combinators); local .conda path deps.
- tasks: env-pinned depends-on ({task,environment,args}); default-environment; MiniJinja + pixi.* vars (is_win!); inputs/outputs caching; args w/ choices (validated: "choose from: …"); multiline=; semantics + set -e; deno builtins cross-platform (cp/mv/rm/mkdir); _hidden tasks; task alias shorthand [{task=..}]; task-level env overrides activation env for that task.
- envs: inline env content ([environments.X.dependencies/tasks/platforms...]); solve-groups; feature channels w/ priority; env-task shadowing; platforms intersection rule.
- platforms: wildcard target selectors [target."cuda-*".tasks] (workspace/feature only, NOT package); pixi workspace platform add --auto-detect; pixi info shows "Minimum platform"; archspec names validated vs bundled db (underscores); CONDA_OVERRIDE_* env vars incl CONDA_OVERRIDE_ARCHSPEC; win has NO default virtual floors.
- env internals: activation shell = bash/cmd; shell-hook; conda-meta/pixi metadata + lock hash; pixi clean [-e]; reflink dedup; PIXI_CACHE_DIR.
- setup-pixi v0.10.0: working-directory input (monorepo fix for our CI!), environments:, frozen/locked, cache-write, activate-environment, global-environments, custom shell wrapper, post-cleanup; rejects cache:true with run-install:false.
- publish/prefix.dev: trusted publishing OIDC (no secrets), --generate-attestation (sigstore); pixi upload; docker multi-stage shell-hook pattern; s3/gcs channels + rattler-index.
- inline package defs on source deps (no manifest needed upstream! alternative wrapper style); rattler-build backend: NO run-exports (use recipe), no binary deps in manifest, custom variant keys → env vars + jinja; incremental builds need OUT-of-root build dir; recipe search order; experimental flag.
- compilers: {lang}_compiler(_version) variants; win family target ok; [package.build.target.<plat>.config] per-platform (extra-args REPLACE base; env/compilers merge per documented behavior).
- cross-compilation: pixi publish --target-platform; multi-output recipes; pin_subpackage; noarch stubs pattern.
